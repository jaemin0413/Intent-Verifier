# HTTPS 링크 배포 검증 · 2026-09-24

목표는 별도 앱 계정 없이 HTTPS 링크로 접속하고, 재시작 뒤에도 프로젝트·Figma 완료본·연결 정보가 유지되게 하는 것이다. 로컬 개발 경로는 유지했다. 제품의 Figma 기획 → 승인 → Notion → Backend 개발 → Java 검증 기준은 변경하지 않았다.

## 구현

- `PUBLIC_ORIGIN`이 있으면 지정한 HTTPS Host·Origin만 받는다. 링크의 256비트 키로 `/api/session`과 Figma 최초 연결을 보호한다. 일반 API는 서버 세션 토큰, 연결된 플러그인은 파일·프로젝트별 Bearer 토큰을 사용한다. 키는 `APP_DATA_DIR/link-key`에 생성·보관된다. 브라우저의 `#access`는 서버 URL이나 HTTP 요청 대상에 포함되지 않고 세션 저장소에서 재사용한다.
- `APP_DATA_DIR`에 상태·Notion 비밀값·Figma 화면·분석 로그·실행 기록·접근 키를 모은다. 실제 배포용 Figma manifest/UI는 `npm run deploy:prepare`로 그 안에 생성하며 HTTPS 도메인을 manifest에 고정한다.
- 홈서버용 Caddyfile, systemd 서비스, 환경 변수 예시와 데이터 이전·백업 절차를 [배포 방법](../implementation/HTTPS-배포.md)에 두었다. 서버 본체는 계속 루프백에서만 듣는다.

## 실행 결과

- `npm test`: **137 PASS / 0 FAIL**. 새 테스트는 키·Host·Origin 거절, 서버 재시작 후 프로젝트/키 복원, HTTPS 플러그인 manifest·요청·연결 링크를 검사한다.
- `npm run prove`: **통과**. 정상 구현 PASS, 정책 위반 FAIL, Fixture/Observation 오류 BLOCKED 구분을 재확인했다. 실행 원본은 `output/proof.json`에 있다.
- 임시 외부 HTTPS 주소 `https://settlement-hip-contrary-wider.trycloudflare.com`에서 Playwright Chromium으로 웹앱을 열고 프로젝트를 추가했다. Node 재시작 후 브라우저 새로고침에서 같은 프로젝트가 보였다. [브라우저 화면](../../output/playwright/remote-library.png)에 보관함 완료본 v1과 화면 1개가 보인다. 임시 주소와 터널은 검증 후 종료했다.
- 동일 HTTPS 주소에서 키 없는 세션 **403**, 키 있는 세션 **200**, Figma CORS preflight **204**, 연결 승인/claim **CONNECTED**, 화면 전송/완료 리비전 **v1**을 확인했다. 재시작 뒤 플러그인 Bearer 토큰, 리비전 v1, 화면 1개, Notion 연결 상태가 남았다.
- 기존 사용자의 Notion 키를 분리된 검증 데이터 디렉터리에 일시 적용했다. 원격 앱 상태에서 연결됨을 확인하고 Notion `GET /v1/users/me` 읽기 요청 **200**을 받았다. 검증 후 임시 서버·터널을 종료하고 키 복사본을 빈 설정으로 덮어썼다. 검증용 화면 데이터는 무시되는 `.tools/remote-smoke-data`에 남겼다.
- `deploy:prepare`의 실제 실행으로 공유 링크와 HTTPS 전용 Figma manifest 생성도 확인했다. 숫자 근거는 [proof JSON](../../output/https-deployment-proof.json)에 있다.

## 남은 조건

실제 Figma 플러그인 창에서의 화면 수집은 이번 임시 연결에서는 수행하지 않았다. 테스트 클라이언트로 플러그인과 동일한 원격 HTTP 흐름을 실행했다. 임시 프로젝트에 승인 명세가 없어 원격 Notion 페이지 발행은 수행하지 않았다. 실제 홈서버의 주소·OS·접속 방식이 없으므로 DNS, 공개 인증서, 재부팅 후 서비스 자동 시작은 현장 검증 전이다. 운영 주소에서 `deploy:prepare`를 다시 실행하고 Figma 플러그인을 가져와야 한다.
