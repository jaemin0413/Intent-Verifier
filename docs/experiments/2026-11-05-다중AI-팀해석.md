# 다중 AI 연결과 팀 공통 해석

2026-11-05. 목표는 홈서버에 띄운 도구로 팀원 모두가 Figma를 같은 해석으로 보는 것이다.

## 바꾼 것

- **AI 연결:** Codex·Claude·Gemini 중 팀이 쓸 AI 하나를 고른다. 모든 응답은 같은 schema 검사를 거치고, 어떤 AI와 모델로 만들었는지 기록한다.
- **같은 해석:** 프로젝트 안에서 내용이 같은 화면은 AI를 다시 호출하지 않고 기존 해석을 연다. 승인된 기준을 바꾸거나 다시 해석하려면 확인을 거친다. 팀 해석 기준 화면에서 정책과 답변 충돌을 본다.
- **결과 신뢰:** Harness가 대상 프로젝트 Bean이 Mock이나 생성 대체 클래스가 아닌지 직접 확인하고, 이 기록이 없으면 PASS를 주지 않는다. 생성 코드 검사기는 Bean Mock, 보안 대체, 리플렉션을 거부한다.
- **재실행:** 컴파일에 실패한 파일을 `src/test`에 남기지 않고, 이전 실패 실행의 파일은 내용이 같을 때만 치운다. 찾지 못한 API의 시나리오만 BLOCKED로 두고 나머지는 실행한다. 경로 변수 이름 차이는 같은 API로 본다.
- **사전 점검:** wrapper, Java, 멀티모듈을 AI 호출 전에 확인한다. 시간 초과와 서버 재시작 중단을 결과에 표시한다.
- **홈서버:** 상태 응답에서 원문과 이력을 빼고 변화가 없으면 304를 준다. `BACKEND_ROOTS` 밖 폴더는 연결도 실행도 거부한다. 전체 프로젝트에 접근하던 플러그인 공용 토큰을 없애고 systemd 제한을 추가했다.
- **범용화:** 프롬프트와 화면, 오류 문구의 특정 프로젝트 전용 표현과 스크랩 전용 버튼을 제거했다.

이 실행은 Claude Sonnet(`claude-sonnet-5-5`)이 한 번에 생성했다. 시나리오 4개 모두 Bean 확인이 통과했고, 신고한 대체 경계는 WebSocket 메시징 템플릿 하나다. 결과는 Codex로 실행한 2026-09-24 실행과 같다. 업로드 시각 최신순 정렬 FAIL도 다시 검출했다. 기대값이나 대상 코드는 바꾸지 않았다.

첫 시도 `1793882543013-native-b53e6e10`은 4 BLOCKED였다. 대상 프로젝트 `build.gradle`에 `useJUnitPlatform()`이 없어 Gradle이 테스트를 찾지 못했다. 커밋 `c3763d7`(2026-10-08)에서 빠졌다. 대상 파일을 고치지 않고 실행 전용 init 스크립트에서 켜도록 바꿨고, 같은 오류에서는 AI에 복구를 요청하지 않게 했다.

## 범용 Gradle 확인

지원 범위는 Gradle wrapper가 있는 단일 모듈 Java Spring Boot 3·JPA 프로젝트로 정했다. Maven과 멀티모듈은 UNVERIFIED다.

`npm run prove:builds`는 어떤 팀 코드와도 무관한 샘플을 만들어 실제 Gradle로 실행한다. 샘플에는 `useJUnitPlatform`과 H2가 없고, 컨트롤러 이름은 `ItemResource`이며, 승인 경로 변수와 코드 변수 이름이 다르다. 결과는 PASS 1, FAIL 1이고 Production 해시는 불변이다. Service를 대체한 코드는 2 BLOCKED로 막혔다.

Windows에서 경로에 한글이 있으면 Gradle 테스트 JVM이 `ClassNotFoundException`으로 실패했다. AI를 호출하기 전에 이유를 알려 주도록 막았다.

## 미확인

- Gemini 실제 호출: API 키가 없어 응답을 흉내 낸 테스트만 통과했다.
- Claude API 키 경로: 실제 키로 호출하지 않았다.
- 새 Harness의 Codex 실행: 이번에는 Claude로만 실제 실행했다.
- 실제 홈서버 배포와 systemd 제한, Figma Plugin 실연결, Notion 실연동, 여러 사람의 동시 사용.
- 조건 Coverage는 그대로다. 시나리오가 없는 Backend 조건은 여전히 미검증으로 남는다.
- AI를 바꿨을 때 해석이 같아지는지는 보장하지 않는다. 같은 해석은 AI 출력의 일치가 아니라 저장된 해석과 승인 기준을 함께 쓰는 방식으로 만든다.

## 2026-11-06 실행 막힘 수정

팀 화면에서 "해시태그 상세" 기능이 2 BLOCKED였다(`1793948017790-native-4452ad50`). 기대값의 `$fixture/tribeId`는 AI가 돌려준 `relations.tribeId`에서 읽는데, AI가 이 규칙을 몰라 `records` 안에 넣는 추측을 반복했다. 마지막 수정 시도는 컴파일에 실패하면서 앞 시도에서 실제로 실행된 시나리오 결과까지 지웠다.

이제 도구가 시나리오의 모든 `$fixture` 참조와 넣을 위치를 AI에게 알려 준다. 마지막 시도가 실행조차 못 하면 앞 시도의 실제 실행 근거로 판정하고, 내부 파일 경로 대신 다음 행동을 보여 준다. 같은 기능을 다시 실행한 `1793949515799-native-fbb0f055`는 2 PASS였다(Claude Sonnet, 첫 시도 컴파일 오류를 두 번째 시도에서 수정). Production 해시는 불변이었다.
